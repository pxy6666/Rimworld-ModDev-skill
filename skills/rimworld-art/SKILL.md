# RimWorld 美术路由

先从 `rimworld-mod` 提供的真实消费者、目标版本、加载根和技术规格确定任务；本技能负责素材制作、对位与视觉证据，不拥有 Def/C# 绑定。

## 分类与必读

一项任务可同时属于多类，必须叠加执行相关合同。

| 任务 | 入口 |
| --- | --- |
| 普通图标、物件、建筑、UI 或单张贴图的生成/编辑 | [图像来源](references/image-sources.md) |
| 多方向、多状态、批量换款、贴格、拼接或统一风格 | [批量 GFX](references/gfx-batch.md)，并按需使用图像来源 |
| Apparel、穿戴图、身体覆盖层或依赖 pawn 身型锚点的素材 | **必须**使用 [Apparel 对位](references/apparel-alignment.md) |
| 飞行、悬浮、抛射物、视差、动画轨迹或任何图层敏感工作 | **必须**使用 [渲染空间](references/render-space.md) |

所有路线都按 [视觉验收](references/visual-acceptance.md) 分开记录文件、绑定、同步与游戏证据。已有合格素材可直接检查和交接，不强制重新生成。

## 工作合同

1. 从真实消费者记录用途、目标版本、路径、加载根、方向/变体、画布、`drawSize`、图形类、图层和 shader；未知项不得靠惯例补全。
2. 只使用当前任务明确授权且实际可用的图像工具或用户素材。不得保存凭证、自动发起付费调用、静默切换来源/模型，或把提示词和占位图写成已完成产物。
3. 按任务类别制作或编辑素材，并保留真实 alpha、消费者映射和所需的对位/渲染证据。
4. 保存来源、授权、实际模型/工具、提示词/参考、最终文件路径与哈希，以及最终文件/合成图/游戏验证证据。未知模型必须标为未知，不得猜测。
5. 将最终文件、路径、消费者和视觉证据交回 `rimworld-mod`，由其实现 Def、C#、`DrawPos`、图层、shader 或框架绑定；`rimworld-art` 不代改这些绑定。
6. 绑定后的错位、缺图、方向错误、遮挡错误或运行时渲染失败交给 `rimworld-debug`，并附消费者、文件哈希、对位或三维渲染合同、复现步骤和现有证据。

## 停止条件

缺少真实工具或授权、目标消费者、匹配的 Apparel 身体基准、稳定画布、可分离图层、目标渲染器证据或必要视觉验证时，停在对应资源缺口并列明后续动作。生成成功、PNG 可打开或静态绑定存在，都不能冒充最终视觉完成。
