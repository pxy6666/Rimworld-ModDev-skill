# 发行包

按工程版本结构收集 About、LoadFolders、有效版本目录和公共资源。多版本目录按声明验证；不把工具自己的工作目录当 mod 发行目录。

按 [迁移内容清单](../../rimworld-debug/references/migration-content.md) 检查每版内容根与实际角色目录、关键定义/补丁/语言/资源。识别junction/symlink/reparse point并核对来源、边界与循环；在新的干净发行目录生成实体内容，或使用实体共享布局，不只把链接本身塞进包。最终从独立包/解压目录再核对，工作区链接可读不代表用户安装后可读。

包内每个支持目标分别核对有效源码/条件符号、框架与引用、当前产物记录/校验值；1.7 成功不能证明 1.6 产物有效。保留旧 DLL 记录其来源和验证，不能冒充新编译。不要误带仅用于编译的 mscorlib、Assembly-CSharp、UnityEngine/UnityStubs、Waylith、0Harmony、系统参考或未授权上游 DLL。

核对独立安装所需文件、资源引用、版本/依赖与许可、用户说明、必要存档/行为测试。只在相关证据存在时标加载或行为通过。

逐项核对资源清单：自带文件进入正确位置，运行时复用有正确提供方/依赖，必要署名保留；区分游戏素材与工坊预览。未满足成品要求的缺项或临时占位不能靠生成 ZIP 掩盖；草稿不进入发行树，参考文件按下述硬门槛核对。

## Reference-only 素材发行硬门槛

1. 收集 [Apparel 对位](../../rimworld-art/references/apparel-alignment.md) 等流程的 reference-only 清单，逐项核对 body/head/baseline 的源路径、本地路径（如有）与文件 SHA-256。保留清单在包外；本工具链优先在项目 `.local/art-references/` 暂存参考文件，不得将其纳入任何内容根、`LoadFolders` 或发行暂存目录。没有使用参考素材时明确记录无此类文件。
2. 打包后、交付或发布前，以实际最终 Mod 子目录为根核对完整 `manifest.json` 的路径和逐文件 SHA-256；若有 ZIP，确认其中的文件路径和内容哈希也与清单一致。统一为 Mod 根相对路径和 `/` 分隔符后比较可映射的参考路径，并将所有参考 SHA-256 与**所有**包内文件哈希比较，不限目录或扩展名。不能用源目录清单或 `.local/` 排除规则代替这一步。
3. **任一参考路径或哈希命中即停止：不得交接、分发或上传。** 移除误带文件及其复制件，重新打包并复核清单；如无法建立完整的参考清单或验证最终包，也不得标记发行通过。记录检查结果和对应清单，重打包后重新检查。

## 生成与交接

打包至新目录，生成 SHA-256 清单与来源记录；不覆盖已有发行包。明确未验证项与发布目标。准备交给 [工坊发布](../../rimworld-publish/SKILL.md) 时，保留 `release-receipt.json`、`manifest.json` 与收据指定的实体 Mod 子目录三者在同一发行目录中；文件清单以 Mod 子目录为根。把约定的验收范围、实测记录与用户接受的例外一并交接；打包收据不替代这些证据。页面描述素材、截图或发布 journal 不复制到发行内容树；描述随发行一并交接给工坊发布（每次发布必交），截图由用户提供。上传不由打包触发。

项目没有配套打包器时，可从本技能仓库的完整 checkout 使用 Python 3.11+ 执行 `python <checkout>/tools/mod_cli.py package --root <Mod工程根> --target <1.6或1.7>`。读取工程 `config/mod.json` 的发行目标及项目身份；有 C# 的工程还需提供当前编译回执或已审查的外部产物记录。打包器使用同一 checkout 的内容根审计，保留目录结构。产物位置与校验状态由命令报告。
