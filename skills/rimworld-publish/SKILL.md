# RimWorld 工坊发布

只上传 [发行准备](../rimworld-release/SKILL.md) 交付的已核验 Mod 目录。缺发行收据、清单或内容校验不一致时回发行准备。不要直接上传源工程、游戏 Mods 目录、ZIP 或 staging 父目录。

每次发布都是完整发布，[必做清单](references/upload.md) 没有可选项：页面描述（带按 About.xml 生成的前置段）、必需项目与 DLC 依赖、其他语言槽、变更说明都是发布内容，用户没有逐项提到也要做。用户只决定可见性（转公开单独确认，新建默认私密）和只有用户能提供的截图（每次都问）。

1. 按 [上传与恢复](references/upload.md) 先运行离线 `plan`：检查发行收据与文件哈希，核对这份包在约定范围内的验收或用户明确接受的未验证项，落实创建或更新目标，备齐页面文案，列出内容与页面改动，保存 journal。缺必做项时 `plan` 直接拒绝，补齐后重跑。
2. 获得对该目标和操作的明确上传授权后，按 [Windows Steam 环境](references/sdk-env.md) 复用用户已登录的桌面 Steam，运行 `upload --journal`。已经明确授权同一份计划的，不重复询问；新增创建、转公开或其它未授权改动先确认变化部分。
3. 新建成功后立即 `bind` 把物品 ID 写回工程 `About/PublishedFileId.txt`，回发行准备重新打包，再计划并提交一次内容。这一轮完成前不算发布完成。
4. 按 journal 报告物品 ID 和每个必做项的状态，有一项没完成就不说发布完成。必需项目或 DLC 依赖读回不一致时，列出让用户在网页手动添加。已知失败只续未完成的操作；超时或结果未知先核实，禁止盲重试或重复创建。发布结果与游戏内加载、行为验收分别报告。

代理不收集 Steam 密码、令牌或验证码。验证发布工具时默认离线或模拟，不拿生产工坊物品试跑。
