# RimWorld 内容制作

## 制作前先整理与审视

按 [workflow.md](references/workflow.md) 执行 Requirement → Plan → Build → Review：整个成品为大循环，每个功能块运行小循环。Build 包括制作 XML/C#/资源，不能理解成收到需求就先编译。先复述需求与验收、给出简短计划并检查，再进入实际制作；只读调查可提前开展。

模糊、零散或冲突需求先整理，对影响玩法/依赖/成品的关键取舍给少量具体选项，取得用户选择后更新计划。明确任务可展示短计划、自检后继续；用户要求先审视计划时必须等待。自检不能代替未决偏好，未回复不算同意。每个小循环只为新出现的重大取舍再问，不重复审批已确定内容。

## 确定范围

读取当前工程约定与用户目标。按 [scope.md](references/scope.md) 选制作范围、实现模式和交付形态，简短说明允许的成果与验收；小改动无需新建工作单。复杂功能用 [feature.md](references/feature.md) 记录连接契约与当前证据。

先区分修改当前工程、新建独立衍生 mod/兼容补丁、直接编辑上游。新独立工程采用自己的 packageId、Def 前缀、命名空间和产物路径；上游仍通过依赖/引用连接，不默认修改它或复用其身份。父目录中的示例配置不替代新工程自己的约定。

已有工程目录只证明已有内容，不能作为本次扩展的授权。完整 mod 可含多个功能块，各块记录范围，整体只验收用户要求的功能。

涉及素材或玩家文案时，按 [assets.md](references/assets.md) 明确本次必要资源、用户已有材料、可提供/复用项目与缺项状态。只请求真正需要用户提供的输入，技术规格由用途和加载接口确定；不把完整素材包设为所有任务前置。

在工程提供本项目 CLI 时：先 `snapshot` 得到基线，再修改；`check --profile L1 --baseline <文件>` 等按选定范围检查本次变化。已有有效环境可复用；第一次使用或版本改变时运行 `doctor`。其他工程使用自己的等价构建和检查，不强加本仓库的布局。

首次或命令无法执行时，先运行不依赖 Python 的 `tools/preflight.ps1`，按需要读项目 rimworld-setup 的准备流程；仅检查当前任务能力，不把全部 MCP 当作制作前置。已有环境可直接继续，用户不清楚目标时才用 rimworld-help 引导。

L5 需要把已选上游程序集加入真实编译引用，并分别核对运行时依赖和加载关系。L6 使用上游原有工程、引用和检查；本项目单程序集 CLI 不是所有上游的通用构建器。具体关系与操作矩阵见 [upstream.md](references/upstream.md)。

## 按功能闭环推进

1. 定义本功能的可观察结果、输入条件和完成标准。
2. 内容主导功能查 Def/父模板与配置接口；系统或显示主导功能查启动、事件/补丁入口和生命周期。记录版本、路径、相关 defName、类型或签名；先找可复用行为，再决定新增哪些类。
3. 按模式写连接契约：内容功能连接 Def 与配置/行为类；系统功能连接入口、服务和状态；显示功能连接事件、数据来源、筛选和渲染。需要时先写接口骨架；只有确需 Def/XML 时才创建相应内容。
4. 写最小完整改动，再核对范围与连接契约。按相关分支读取 [xml.md](references/xml.md)、[csharp.md](references/csharp.md)、[upstream.md](references/upstream.md)、[assets.md](references/assets.md)，无需全部加载。
5. 按 [verification.md](references/verification.md) 选择检查。涉及源码时编译完整工程；功能模块完成后检查它们之间的连接，再做组合行为验证。
6. 对相关失败修复并复验；达到约定验收后结束。游戏操作无法执行时交付复现步骤，保留未验证项。

系统/显示主导任务读取 [runtime.md](references/runtime.md)。C# 占比不决定新级别；L3/L5 可完整交付无新增 Def 的 mod。混合 mod 按功能选择模式，不要求每块先创建物品。

修改接口后重新核对使用它的 Def 和调用方；改变引用后核对代码读取与加载。依据依赖关系失效相关证据，避免每轮重新生成全部文件。

## 工具与边界

- 原始 XML 证明模板、输入与补丁目标；运行时 Def 快照证明特定测试组合的最终值；源码/DLL 证明字段和行为。三者不能互相冒充。
- RimSage、RimSearcher、DecompilerServer、RiMCP 按问题选用，读取实际工具定义。无工具时允许查本地 XML、公开上游源码或已有版本明确的材料，不自动改客户端配置。
- 空查询先检查命名、上下文、类型、加载列表和索引；无法确认关键外部接口时暂停依赖该接口的部分。新 Def 无须预先在游戏索引中存在。
- 允许为纯 XML 任务查看 DLL。成果扩展需符合用户范围；明确限制无法满足时说明原因并请求必要决定，其余已授权工作继续。
- 多个必要补丁允许共存；每个记录目标、目的、版本和作用范围。Prefix/Postfix 按执行时机选择，Transpiler 需说明其它方式为何不够。
- 通过需求选择与计划审视闸门后，范围内的制作、检查和编译连续完成；变化带来新的重大取舍时回到相关 Requirement/Plan。安装/发布/破坏性操作按实际授权处理。

## 交付

报告产出、范围检查、编译及已实测结果，列出未验证项。完整性取决于用户功能是否能获取、使用并表现正确；已有工程的小修不重建完整包。相关 CLI：`tools/mod.ps1`，详见项目 `docs/cli-workflow.md`。
