# 剧情状态与存档

任务跨阶段、地图、事件或存档时读取。状态所有者与恢复条件落到同一份 [任务与地图交接记录](feature.md#任务与地图交接)。信号及事件入口见 [事件发放与任务信号](quest-events.md)。

## 按生命周期选所有者

| 要保存的状态 | 优先考虑 | 原版对照 |
| --- | --- | --- |
| 同一任务的连续阶段、等待、目标和结局 | 任务零件的持久字段与对象引用 | Anomaly `QuestNode_Root_VoidAwakening` 在一个 Quest 中安排波次、终局和清理，`QuestPart_MetalHell` 保存子地图与 Pawn 引用。 |
| 可独立结束、并行或重发的子任务 | 父任务的调度 Part 保存发放资格与时点，单独任务保存各自进度 | Odyssey 引力船的 `QuestPart_SubquestGenerator_Gravcores`，巢穴成功结束父子任务，地图移除可只使该子任务失败。 |
| 多地点、多个任务或独立事件共享的阶段 | 作用域与项目匹配的游戏或世界组件 | Anomaly `GameComponent_Anomaly.SetLevel` 保存巨石进度并派发阶段事件，达到条件启动独立终局。 |
| 地点能进多久、入口是否关闭、设施使用状态 | `WorldObjectComp`、`MapComponent`、`ThingComp` 或实际对象 | Anomaly 地坑的表层入口保存口袋地图及关闭计时，地下目标死亡经地图组件通知它坍塌。 |

这些案例来自 RimWorld 1.7.5014 rev1195 的本机 XML 和同构建方法核对。XML 从 `Odyssey/Defs/QuestScriptDefs/Script_GravShip.xml`、`Anomaly/Defs/Misc/MonolithLevels.xml`、`Anomaly/Defs/QuestScriptDefs/Script_EndGame_VoidAwakening.xml` 和 `Anomaly/Defs/MapGeneration/UndercaveMapGenerator.xml` 定位。实际读档、事件顺序和跨地图组合还需验证。

## 状态边界与去重

- `QuestNode_SubScript` 复用当前任务及 `Slate`，可显式传入和返回变量。独立任务使用新的 `Slate`，只传它确实要消费的输入。`Slate` 用于生成阶段，运行期引用和选择放进持久所有者。用枚举或值传递已选择的路线。跨地图继续同一个 Pawn 或物品时保存可恢复的对象引用，定义对象消失后的业务结果。不能只凭同一个 Def 或显示名重新识别对象。
- 多个入点汇入同一故事时，由持久所有者保存本轮实例、已进入的阶段和结算结果。发放或结算前核对当前阶段、实例和目标身份。对读档、重新进图或回调重入，查持久阶段及可核实结果再恢复。奖励、新任务或其他副作用可能分步完成时，单独持久记录处理进度，定义部分成功怎样继续。
- 有数值或计时边界时写清等号归属。若 `tick < 期限` 时允许交付，超时应从 `tick >= 期限` 开始。按玩法选定边界，并验证边界前、恰好等于和边界后。计数可跨过阈值时验证跳过等值的情况。
- 两个信号可能竞争时，说明成功、失败或取消的优先级。若同一 tick 的结果需要比较，核对实际回调顺序，必要时收齐结果再结算。重复信号在阶段已变更后由守卫条件过滤。预期信号缺失时，按可观察事实恢复，或走已约定的替代、超时、失败和重试路径。
- 单独判断正常离开、地图移除、地点或目标销毁，以及流程自己的清理。按实际发信对象核对 `MapRemoved` 与 `Destroyed`，地点可能在失去地图后仍存在。若结局清理也触发已监听的信号，检查已进入终态的任务怎样处理它。重试明确保留的成果和旧实例何时关闭。

## 兼容旧存档与回归

更换节点树时，已接取任务可能仍保存旧任务零件和引用。先确认受影响的存档、是否能用已知的旧字段恢复进度，以及找不到目标时的退出策略。新增持久字段有明确默认和加载恢复。若要改动已经生效的旧任务，优先保持已发报酬、既有角色及任务身份，按明确的兼容设计补齐、收尾或保留旧逻辑。

按受影响状态选择回归点，如入图前、阶段切换前后、跨图之后或结算前后。在这些点复查本次相关的边界、重复或竞争信号、对象消失和读档结果。静态路径审查和读档实测分别记录。
