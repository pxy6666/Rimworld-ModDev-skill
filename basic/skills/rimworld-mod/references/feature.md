# 功能闭环与连接契约

复杂功能在工作单中记录下列内容；简单修改只简要说明相关项。

本表承载 [workflow.md](workflow.md) 的大小循环和 [project-state.md](project-state.md) 的续作入口。实施前记录需求、选择、具体计划与用户确认依据，技术自检单列；完成后回填验收。代理维护，不要求玩家自己填表。

| 项 | 记录 |
| --- | --- |
| 功能与验收 | 玩家怎样获取、操作、观察结果；数值和边界 |
| 需求与计划状态 | 用户原意、代理建议/假设、已选方案、待答问题；当前计划与审视依据 |
| 功能标识与续作 | 稳定标识、相关文件/索引、当前步骤、下一动作、待选/阻塞项、停止位置 |
| 用途与真实类型 | 玩家获取/操作、触发/执行/输出链；Def/配置实际类型与 Class，候选 C# 及必要性 |
| 范围、模式与成品 | L1-L6；内容/系统/显示；edit/standalone/complete/release；明确限制 |
| 制作模式 | 项目默认/功能覆盖：用户控制、CLI 决定或混合；关键锁定项及委托边界 |
| 内容连接（适用时） | Def 类型、defName、ParentName 模板、XML 配置类型 → 行为类 |
| 运行连接（适用时） | 启动/事件/查询 → 处理服务 → 输出；真实签名、时机与作用对象 |
| 配置来源 | 每项要求状态、有效值/单位、唯一权威位置与读取者；用户/模板默认/CLI/占位/未定来源及依据 |
| 资源契约（适用时） | 用途与必要性、用户/生成/复用/占位来源、文件/引用、规格与状态；谁补齐及剩余验证 |
| 状态 | 所属对象、序列化键、默认值、加载后恢复方式 |
| 上游 | 调用/衍生/修正；硬依赖/可选；版本与加载方案 |
| 证据 | 问题与结论、工具/文件/程序集/快照版本、路径/哈希、类型/Class、条件与运行组合；回退原因、未确认项与需重验项 |
| 验证 | 静态、编译、加载、行为、存档、视觉各自结果 |

先完成最小能获取和使用的内容，再逐个补功能；XML/C# 参考页在需要时读取，不能无条件循环生成。

多个配置项可用子表：`类型/Class + 路径或接口 | 功能条件/要求状态 | 有效值/单位 | 值来源/依据 | 权威位置/读取者 | 验证`，按 [contracts.md](contracts.md) 判断真正缺项。已核实继承/默认值可引用证据，不重复抄全部字段。

显示/系统功能的最小闭环是可触发并观察预期结果，不要求制作/获取一个物品。显示功能明确数值来自输入请求、最终结算、护盾吸收还是聚合；瞬时显示、缓存、用户设置和游戏状态分别记录生命周期及持久化需求。

武器例：ThingDef 的 verbClass 连接攻击类；comps 的 Class 连接 CompProperties，其构造设置 compClass；Projectile 引用 DamageDef，workerClass 连接伤害逻辑；HediffDef 连接状态类。仅原版无合适受伤入口时增加局部 Harmony。每条边都验证类型、配置读取和执行时机。

数据定义、逻辑与文案不要各自保存一套冲突数字。修改某个端点后验证相关引用者，功能组合完成后验证交互。C# 全局服务和补丁可无新增 Def，但必须有明确触发与作用范围。
