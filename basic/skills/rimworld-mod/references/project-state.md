# 持久记录与增量续作

真实文件/接口是实现事实依据，文档保存需求、选择、证据和进度。发现漂移先核对记录，不用过期文档覆盖代码数值。

## 四类信息入口

复用目标工程 README、工作单、台账或状态文件。无约定时可在 `docs/development/` 保存；小任务可共用一份短记录，不强制四个文件或新状态框架。

| 信息 | 最少内容 |
| --- | --- |
| 项目概览 | 位置/身份、版本、目标/限制、默认制作模式、上游/加载、开发阶段 |
| 功能记录 | 稳定标识、需求/验收、用途/真实类型、契约、计划及确认依据、模式覆盖、值/资源来源、证据、验证、未决项 |
| 内容/引用索引 | 自有 Def/type 身份与文件、提供方、关联引用/消费者、影响功能；不复制游戏全索引 |
| 当前检查点 | 当前块/步骤、待选项/缺证据、下一动作、最近交付/停止位置、需重验项 |

复杂块用 [feature.md](feature.md)。保存证据位置与结论，不堆源码/工具全返回或密钥。本机快照/日志用工程本地目录；共享记录不应只有临时路径而无可理解结论。

## 恢复顺序

1. 判断继续、添加、调整、停止某块或结束阶段；保留未撤销的原目标，新增需求形成增量，不能默默改旧验收。
2. 读概览/检查点，再只读相关功能与依赖；核对真实文件、构建/日志及用户最新指示。
3. 沿用有效选择、模式、计划确认与证据；新增/变化部分回到相应需求/计划步骤，不重问全部问题。
4. 从下一动作继续；实际改动前读本块契约，相关阶段结束/交付前更新记录，避免压缩后遗忘。

## 复用与局部失效

证据键包括游戏/上游版本、来源文件/程序集路径与哈希（可获得时）、类型/Class、查询范围和条件。运行证据另列 DLC、mod 版本、加载顺序与组合。通用版本标签不能冒充精确来源已验证。

来源/条件变化只失效相关结论与验证：模板/字段影响继承和消费者；签名影响调用方；资源绑定影响加载/视觉；组合变化影响运行结果。缓存有效性未知时标未验证并核对，不盲用或重查全部。

## 交付与停止

项目生命周期和本次增量分开。增量达标后交付并等待新需求，不在无目标时循环生产；未游戏实测留场景/步骤，记录的“完成”不是游戏证据。

明确中止某块时保存停止位置、文件、未决项及对其它块影响，不自动删除、回滚、发布或继续。恢复时沿用有效记录，整个阶段收尾时再查组合与交付。
