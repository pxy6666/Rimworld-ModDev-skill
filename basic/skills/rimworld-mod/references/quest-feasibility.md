# 剧情演出与玩家动作的可行性

对剧情的关键情节核对“玩家在哪看到什么、当时能做什么、世界会怎样变化”。优先查会改变故事方向或依赖的点，例如开局地图、强制交互、跨地图保留同一 Pawn、任务选项、特殊按钮、镜头和角色演出。日常对白或已经有证据的简单行为沿用已有记录。

## 在同一阶段记录内补证据

- **构思初查。** 推荐具体路线、演出或状态图前，按 [本地查证](local-lookup.md) 查看目标版本、允许的 DLC、已选上游及已有证据。确认相近案例用的界面、触发方式和玩家控制权。像“进遗迹就开始对话”这样的要求要查实际是信件、可选对话、Pawn 行为还是脚本演出，有选择时确认操作入口和可用时机。标明已有路径、需要扩展及仍待核对的条件。版本或依赖尚未选定时，可带着明确假设继续构思。
- **计划确证。** 计划自检时补齐会影响玩家体验、依赖或验收的证据，核对实际入口、条件、交互与反馈、消费者和结果是否在允许范围内。沿用 [任务与地图交接](feature.md#任务与地图交接) 中的同一阶段记录，只补缺失证据或变更后受影响的部分。

例如“抵达中继站后接到可选呼叫”，在这条阶段记录先写玩家看到信件、随后能与终端互动。再把地图生成信号、信件、终端和选项消费者的实际入口填回原记录。验收用真正的进图、关信、操作终端、选择和退出流程。

只看到文本或类名时，继续定位调用。仅实机能确认的环节，可做已授权的小范围验证，或标待证并继续其他块。发现会改变已确认体验或依赖的限制时，带着可行方案回到受影响的选择。区分原版依据、已验证的自定义接入和本次 Mod 的实际表现。
