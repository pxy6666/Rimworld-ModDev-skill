# 任务、剧情与地图的入口和交接

先确定用户要交付什么、已有哪一部分。用户在制作请求中描述了剧情、任务、事件、探索地点或地图场景，就按下表选择并读取相应 `SKILL.md`，即使没写技能名。根据玩法识别，如“开局来信”“放弃后隔几天重发”“做一座有守卫和撤离点的地下设施”。偶然提及剧情或只修改武器、数值、贴图时按实际制作范围处理。各分支共用 [制作循环](workflow.md) 和 [项目记录](project-state.md) 中的目标版本、计划、制作模式、已确认范围与检查点。

| 当前需要 | 入口 |
| --- | --- |
| 讨论剧情方向、开局或阶段设计 | [剧情构思](../../rimworld-story-design/SKILL.md) |
| 将已有设计做成任务、事件或任务链 | [任务制作](../../rimworld-quest-build/SKILL.md) |
| 制作任务地点、地图结构、刷新或布置 | [地图制作](../../rimworld-map-build/SKILL.md) |

## 一次总计划，按依赖制作

1. 主制作流程接收已确认的构思或现有设计，在 [任务与地图交接](feature.md#任务与地图交接) 中列出本次功能块、需要的占位及最小可验收路径。专项补齐自己的证据和实际接口。
2. 按接口和依赖排序。任务可先确定信号，地图生成目标后联调；也可以先做能决定玩法的场景原型。小改只走当前块和受影响的联动。独立查证或制作可按 [并行分工](parallel-work.md) 执行。
3. 新物品或 C# 功能走对应版本制作流程，贴图走 [资源分支](assets.md)。在原待制作项记录进度，补齐后回消费方换入正式产物并复验。按公共流程审视影响已确认玩法、终点或依赖的变更。

## 集成验收

任务与场景联动时，从本次涉及的入点用真实方式发放和接取任务，进图找到绑定目标，完成互动、返程、结算及清理。检查任务提示与实际行为一致，临时目标和素材符合已确认的交付边界。按影响选 [状态与存档](quest-state.md) 的边界和读档回归、[地图验收](scene-generation.md#验收场景) 的种子和入口回归，以及 [关键场景通读](player-facing-text.md#关键场景的通读验收)。单事件和独立地图按 [成品验收](verification.md) 的相应范围处理。
