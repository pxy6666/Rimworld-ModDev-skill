# Requirement → Plan → Build → Review

Build 是实际制作 XML/C#/资源，编译只是检查之一。先按 [project-state.md](project-state.md) 恢复项目和当前功能；没有记录时创建与规模相称的入口。代理整理口语需求和文档，不要求玩家先写规格。

## 大循环：成品或本次增量

1. **分解需求**：提取玩家目标、获取/操作、触发、结果、版本、限制和验收；区分明确要求、代理建议与待选项，已有工程不自动授权扩展。
2. **用途与类型初判**：按 [classification.md](classification.md) 列功能、实际 Def/配置或事件/服务类型、运行链及候选 C#。初判待查证，不由名字、贴图或根标签直接套模板。
3. **确认大方向**：存在多个玩法解释、冲突限制或依赖/成品方向未定时，给少量选项并等待。调查可继续，不实现未选方案。
4. **分析上游**：判断原版、已选库/内容 mod 能提供什么；按 [upstream.md](upstream.md) 分开记调用/衍生/修正、硬依赖/可选、版本与加载，不为可能用到的框架先加依赖。
5. **查证与配置契约**：按 [contracts.md](contracts.md) 复用证据、优先 MCP 小查询，必要时查源码/DLL、原始 XML 和运行时 Def；确认类型、字段、继承/默认、引用和执行链，保存结论与未验证项供制作读取。
6. **计划审视**：列功能顺序、改动范围、资源策略、配置缺项、验证与未决项，先技术自检，再展示给用户确认具体计划与制作模式。
7. **功能制作**：已确认的块按依赖顺序运行小循环，不因切换 XML/C# 分支重新规划整个 mod。
8. **整体验收**：逐项检查获取、触发、组合、依赖、资源及相关存档；失败回相关块，需求变化回相关需求/计划。分开报告静态、编译、加载、行为、存档与视觉，未游戏实测提供具体步骤。

## 选择与计划确认

每轮围绕 1–3 个影响结果的决定给易懂选项，每项一般 2–3 个方案，说明推荐与影响。不按消息长短判断明确程度，不给完整技术问卷；玩家选择结果，代理查证类名、字段、枚举和引用身份。

计划至少含目标/验收、范围/限制、步骤、资源/参数模式、验证与未决项。小改可用数句，复杂块用 [feature.md](feature.md)。**开始实际制作前需有用户对该具体计划的确认依据，技术自检不能替代用户确认。**

- 新计划展示后等待确认；推荐项预选、未回复或超时不是同意。可继续调查、写记录、拟方案，不先实现未确认方案或调用其付费资源。
- 已明确同意的讨论方案/计划继续有效，记录范围；“按上述方案做”是确认，不再问同一问题。用户明确委托本轮规划和实施、没有未决偏好且在授权内时，记录委托范围并展示执行计划，不制造重复审批。
- 普通“制作一个 mod”或“数值你定”不等于免确认计划；自主规划实施需明确委托，例如“由你规划并实施，不必等我再批计划”。授权依据要能指出具体用户表述，不能代理自行推定。
- 可确认已确定的第一块，后续保持待定，不能把局部确认记成全 mod 通过。新的重大玩法、依赖或成品取舍只确认变更部分。
- 计划内技术实现、常规修复、检查与编译连续完成。排错调查/原工程编译取证、已定成果打包不伪造新玩法计划；新增功能或改变玩家选择时回这里。

自检核对需求覆盖、六种范围/限制、类型与连接、接口证据、资源和验证、阻塞项。代理先修正技术问题，不让玩家解决技术错误。

## 制作模式：只处理真正未定项

先核对明确值、模板、继承、合法默认及是否满足目标，再处理实际缺项。模式按项目保存，可按功能覆盖；没有既有选择/授权时与计划一起让用户选择：

| 模式 | 未定玩法数值/资源怎样补齐 |
| --- | --- |
| 用户控制 | 提供参照、合理候选与影响，等用户决定后写入；待答仅阻塞依赖部分 |
| CLI 决定 | 参照同用途、匹配版本的原版/已选上游，记录理由与最终值；不新增功能或覆盖明确值 |
| 混合 | 用户锁定关键项，其余明确委托；边界未知的关键取舍先问 |

“数值合理即可”“贴图复用原版”等已有明确授权可直接记录，不重复询问。模式不替代计划确认或扩大范围；技术未知继续取证。保存参数单位、唯一权威位置、读取者和值来源，避免代码、XML、文案各留一套数字。

## 小循环：一个功能块

1. 恢复本块已确认目标、模式、限制、记录与依赖，核对文件漂移。
2. 确认用途、真实类型与执行链；与初判不同则更新契约，涉及玩家方向变化才返回选择。
3. 查对应制作范围/契约，核对模板/默认和必要条件；真正缺项按模式集中解决，高频不自动成为必填问卷。
4. 有必要资源才按 [assets.md](assets.md) 准备；缺资源只暂停依赖部分，独立的已确认部分可继续。
5. 制作最小完整功能，按需读取 XML/C#/上游/运行分支，保存进展，不反复生成全部文件。
6. 审核目标偏离、端点连接、引用与配置，运行相关检查，修受影响部分并更新检查点与证据。

各块完成后回整体 Review。增量完成后交付并等待新需求；项目可保持开放。停止某块时保存位置和遗留影响，不自动删除或无目标持续生产。
