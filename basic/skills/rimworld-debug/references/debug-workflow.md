# 公共排错过程

先读取工程约定、用户表现与 [目标证据契约](../../rimworld-mod/references/version-data.md)，恢复 [检查点](../../rimworld-mod/references/project-state.md)。明确目标版本、复现、DLC/mod 顺序、当前产物和日志会话；详细方法见 [diagnosis.md](diagnosis.md)。已有具体授权和证据复用，不重做全部制作计划。

1. 区分 XML/引用/程序集/Harmony/行为/存档/视觉/性能问题。
2. 获取最早相关堆栈和触发上下文、重复频率；跨 mod 堆栈未出现自己的名字也可能相关。
3. 查相应版本画像、异常或符号条目，按 [契约检索](../../rimworld-mod/references/contracts.md) 局部核对原始 XML、运行 Def、源码/DLL；空结果先查命名、加载和覆盖。
4. 在任务范围内做最小修复，检查/需要时编译，复现原问题及相关相邻场景。
5. 更新功能/证据/检查点，分别报告静态、编译、加载、实际触发及未验证项。

1.7 缺失接口/绑定或迁移问题按 [兼容方向](migration-1.7.md)；1.6 任务只查其画像与依赖，不读取 Harmony 3 规则。菜单/地图能进但重复报错或静默失效，按 [地图后诊断](post-map-debug.md)；首次/重复/连续运行及相关生命周期分开，无日志不证明行为或性能。

物品/研究/工作类型不出现、Failed to find或注册数量为0，先按 [内容加载对照](migration-content.md) 查目标实际内容根、关键Def及补丁是否被读入，再查消费者和接口；不要从编译成功跳过内容链。

关键源码/上游或能力不足时保留缺口，其余工作继续。MCP 本身不可用进入 setup 检查有关能力，不安装所有工具。目标工程提供 mod.ps1 时可使用 doctor/check/build/log，否则采用原工程方式；日志与构建绑定实际目标，不启动游戏或改配置来替用户完成未授权动作。

新玩法、依赖、资源或重大取舍回 [制作计划](../../rimworld-mod/references/workflow.md) 的变更部分；不循环调用入口或重新询问既有选择。保留身份或明确序列化迁移；性能结论要有测量。多个独立调查/修复块按 [并行分工](../../rimworld-mod/references/parallel-work.md) 主动评估子 agent，最终合并与验收统一协调。
