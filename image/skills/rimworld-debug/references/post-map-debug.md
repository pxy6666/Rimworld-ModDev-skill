# 进地图后的循环报错与功能失效

用于“菜单/地图能进，但之后出错、功能不工作、重复 UI/提示或卡顿”的诊断；1.7 迁移也必需这个分支。首先恢复功能契约/检查点，读取本次真实日志，明确构建、DLL、上游组合、存档与触发条件。工具仅辅助取证，技能不自动启动游戏或改启用列表。

## 为实际功能建立触发清单

| 阶段/动作 | 必须观察 |
| --- | --- |
| 加载/菜单 | 程序集、类/Def、补丁与初始化，不用菜单出现替代这些证据 |
| 创建 Game/地图 | 游戏/Map/World 组件与 Def 实例能否初始化 |
| 首次触发 | 对应按钮/页签、攻击、生产、事件、库调用等是否产生约定结果 |
| 重复触发 | 关闭重开、连续操作/战斗/事件，是否重复注册、重复效果或状态残留 |
| 连续运行 | 固定场景下的 tick/绘制/定时任务、暂停/变速与错误增长 |
| 生命周期 | 切地图、对象销毁、保存/读档及重进游戏，是否持有旧对象或漏清理 |
| 相关组合 | 库的最小消费者及实际下游；可选兼容按有/无；只测与接口有关的组合 |

功能矩阵按项目实际职责取项，避免一个 mod 只测启动；也不要求普通数值 patch 测全部 GUI/音频。记录动作、预期/实际、日志区间、场景/次数与结论：通过、失败、未验证、不适用。

## 循环报错：追到第一次失败和重复触发者

1. 在触发前保存日志基线与状态；触发后再截取新增长区间。1.7 优先候选为配置目录 `Logs/Player.log`，仍查日志头/正文版本与时间，旧根目录日志可能属于 1.6。
2. 记录最早相关异常、完整内部异常/堆栈与引用号；按引用号或完整栈归组，重复行链接回首次栈。归组不等于根因判定；不同异常不能因相似文字混成一个。
3. 对每组记录首次/最后时间、次数与触发阶段，关联 tick、OnGUI/绘制、事件回调、定时器或静态初始化。日志往往显示受害者，继续查更早的类解析、初始化或补丁失败。

   栈中没有本mod名字不足以判无关，栈出现原版/DLC也不足以判其为根因。命令栏/征召受影响而栈在其它按钮时，追首次异常、缺失/重复定义、空请求、加载来源和补丁消费者；界面绘制被打断是待查因果链，不能只凭末尾一条栈确定责任方。
4. 静态构造失败时查初始 inner exception、依赖/绑定与重复读取它的服务。失败初始化的会话内结果不适合干净回归；重新启动需用户授权或由用户完成。
5. 比较等长时间或等触发次数的前后窗口；仅清日志、暂停游戏、关闭界面、禁用触发者或只输出一次会降低次数，但不能证明功能修复。没有清楚场景/日志区间时，不给绝对“循环已消失”。

例如先查兼容表 RW17-018 的 InitPatches/tick 路径，再查实际绑定条目。单纯给后续访问加 catch/null guard 可能只藏住初始化失败和失效功能。

## 没有异常但功能失效

从契约逐边检查：`操作/事件 → 注册/入口 → 对象与数据 → 处理/配置 → 状态/输出`。分别证明入口触发、关键条件满足及结果正确；只看注册或日志无异常不能证明这条链成立。

重点检查：补丁未安装/打错目标、按钮未连接、错误目标对象、配置/数据更新没有传递、订阅重复或未恢复、默认 shader/无声等回退、空引用被吞掉、设置未生效。允许在已授权修复内增加局部可关闭的诊断计数/日志；不在高频入口无限输出，不把诊断副作用当正式功能。

UI 列表/点击操作查实际数据和焦点；只显示功能查原结算保持；库查消费者输入/返回和异常路径；状态系统查读档恢复和旧引用失效。结果变化需对照用户原要求，不能把删功能后的“不报错”判完整迁移。

## 修复、降级和交付

修复受影响入口/生命周期并复验原场景、重复触发和相关边界，源码有改动才重建对应程序集；保持身份/存档键。依失效机制的旧优化默认不迁移，依据 [migration-1.7.md](migration-1.7.md) 说明范围；移除/禁用/替代核心功能需要用户明确选择。

交付区分：根因修复、用户接受的降级、诊断隔离、阻塞或未验证。压制报错、只进地图、短暂运行和历史日志均不能升级为完整验收。保存新证据、功能矩阵与检查点，避免下一次再查全量旧 API。
