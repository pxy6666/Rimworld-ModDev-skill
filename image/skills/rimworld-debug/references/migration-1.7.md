# 1.6 → 1.7：兼容查表与风险分支

迁移、缺失接口、Harmony 绑定或 1.7 功能异常时读取。六种制作范围仍按原规则选择；这里决定诊断/适配路线，不新增级别，也不默认新增 Harmony。

## 先查表，命中后局部查证

维护数据是 [compatibility-1.7.json](compatibility-1.7.json)，程序入口为 [compatibility.py](../scripts/compatibility.py)。仅含已调查的问题与方向，不是全部 1.7 API 或自动替换规则；静态基线 1.7.4977 rev1248，历史运行报告来自 1.7.4976 rev1043。

用实际可用 Python 执行当前技能目录内脚本，例如：

```text
python <当前技能>/scripts/compatibility.py query --query HasVector --game-version "1.7.4977 rev1248"
python <当前技能>/scripts/compatibility.py query --id RW17-018
python <当前技能>/scripts/compatibility.py query --profile ui --limit 3
python <当前技能>/scripts/compatibility.py table
```

目录以所选 Basic/Image 的真实技能位置为准，不要求工程提供另一套 CLI。无 Python 时可搜索 JSON 的 symbol/aliases/id，只读命中条目与来源，不把整份目录塞入上下文。

1. 从异常、调用或 XML 引用取出真实 owner、接口、重载/ref/out 与使用位置；原名查不到时查别名/症状。多条命中时核对具体签名和消费者，不取第一项自动套用。
2. 分开读 observed、direction、caveats、tests、recipeStatus 和 applicability。接口状态不等于方案已验证，所有种子记录尚未完成目标构建游戏回归。
3. 与项目证据核对构建、上游版本及相关程序集哈希。脚本可用 `--fingerprints <JSON>` 读取 `{"UnityStubs":"实际64位SHA256", "Assembly-CSharp":"实际64位SHA256"}` 等实际记录；不加载程序集、不访问网络、不改工程。版本匹配但哈希未提供只表示 hashes_unchecked。
4. 来源变化、缺证据或未收录时，只查相关接口、调用和条件。仍按能力优先匹配版本 MCP/缓存，不每次重爬两版全部源码。
5. 功能改变、移除、降级或新依赖依目标项目计划确认；技术路线不能把用户原功能悄悄删掉。记录采用条目、差异、用户选择、验证与检查点。

更新条目先补局部证据，保持 id 稳定，分开静态事实、候选方向与实际游戏结果；历史会话不能升级为新构建通过。表内未列出的接口不代表兼容，不凭类型名字相似补调用。

## 按功能选重点，不按 mod 名称定罪

| 功能分支 | 重点取证与测试 |
| --- | --- |
| UI 修改 | 目标 owner/instance、字段/集合绑定、输入/焦点、GUI 状态；开关/快捷键、暂停/缩放及相关组合 |
| Unity 底层、图形/音频 | 实际调用成员/重载、资源/线程/回调与释放；不能只确认类型存在；测试首次和重复使用、切图与资源失败 |
| 优化 | 先判断原优化机制是否仍成立；已失效的旧机制默认不进入迁移制作，不能为了保留优化名义接新补丁 |
| lib/框架 | 自身初始化/公开接口、实际加载目录和下游调用/配置消费者；库能加载不代表下游能用 |
| 新界面/完整系统 | 注册、服务/状态、数据获取、交互/输出与生命周期；每条功能链独立闭环，反复使用及读档 |
| 非规范/内部接口耦合 | 仿类、反射字符串、生成方法/token、私有字段与 IL 假设；按真实目标和消费者查证，优先稳定扩展点 |
| XML 内容/补丁 | 类引用/Def/模板/上游提供方；若用框架或 shader，也进入对应分支；纯 XML 不强查全部 C# |

这些是调查优先级，一个 mod 可跨多个分支；不能据标签宣告有错或强制重编。发现遗漏引用/依赖时回到实际加载链。

## 优化排除与迁移契约

确认旧优化依赖已失效的 Unity/Burst/加载内部机制时，默认终止该优化块迁移，保存原因；仍可诊断造成的报错，用户授权调整启用列表时再隔离。独立有效块不自动删除。用户需要针对 1.7 的新优化时另立需求/计划，先测瓶颈与正确性，不能沿用旧收益声明。依旧有效接口的普通优化也需实测，不能把所有优化 mod 排除。

每个接口记录：`旧接口/使用位置 → 旧职责 → 当前状态/证据 → 表条目/候选路线 → 条件/范围 → 功能取舍 → 测试结果`。缺失的方法不能作为现成 Harmony 目标，同名扩展不能修复旧 DLL 成员绑定，不把旧 Unity/游戏 DLL 打进包。

无源码、关键上游未兼容或缺能力时标阻塞/可接受的降级选择；不装作存在等价新 API。旧 DLL 先检查实际功能，确需重编才修改构建；保留 1.6 时隔离输出，不能让 net10.0 产物覆盖旧目录。
