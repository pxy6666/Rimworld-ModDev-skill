# RimWorld 诊断

读取工程约定和用户表现。先明确复现步骤、目标版本、DLC/mod 顺序、当前构建和日志会话。详细操作见 [diagnosis.md](references/diagnosis.md)。已有日志与工具优先复用，不要求重新建立整个项目。

命令、MCP 或索引本身不可用时先按项目 rimworld-setup 流程检查对应环境层；需要时用无 Python 依赖的 preflight.ps1。已有源码/日志可以继续分析，不因可选工具缺失放弃无关任务。

1. 区分加载/XML 引用/程序集/Harmony/行为/存档/视觉/性能问题。
2. 获取最早相关堆栈与上下文，对比既有错误频率和新表现；未出现自己名字的跨 mod 错误也可能相关。
3. 建立有依据的假设，核对原始 XML、运行 Def、源码/DLL；检索为空先查上下文。
4. 做任务范围内最小修复，再检查和编译，复现原问题及受影响相邻情况。
5. 报告证据、修复和验证状态；不能复现或缺会话数据时说明具体未决点。

明确用户限制不得越过。新的 Def、DLL、依赖或全局补丁先分析必要性；已有授权可更新工作记录，重大未决取舍再提问。普通排错不需要角色讨论或每步确认。

版本迁移需比较接口/字段/目录和序列化变化，保持内容身份或提供明确迁移。性能问题使用实际执行量/测量，日志无异常不能证明速度或玩法正确。

本项目 `tools/mod.ps1 log --file <日志>` 保存分析与原始日志副本；构建默认仅输出本地。游戏启动、安装与发布按任务授权处理。
