# RimWorld 内容制作

## 制作前先整理与审视

先按 [project-state.md](references/project-state.md) 恢复工程、相关功能和检查点；识别继续、新增、调整或停止。按 [workflow.md](references/workflow.md) 执行 Requirement → Plan → Build → Review：成品/增量为大循环，功能块为小循环。Build 包括实际 XML/C#/资源制作，不能理解成收到需求就先编译；只读调查可提前开展。

先分解需求并按 [classification.md](references/classification.md) 判断用途、真实类型、执行链和候选 C#，再确定上游与配置契约。大方向不确定时给少量玩法选项。展示经过技术自检的具体计划，记录用户确认及用户控制/CLI 决定/混合模式后制作；自检、未回复不算确认。已有针对该计划的明确同意或规划实施委托可沿用，不重复审批；新取舍仅返回相关部分。

## 确定范围

读取工程约定。按 [scope.md](references/scope.md) 选范围、模式和交付形态；六种范围不代替真实类型或要求逐级执行。用 [feature.md](references/feature.md) 保存契约、选择与证据，小改可用短记录，不强加独立工作单。

先区分修改当前工程、新建独立衍生 mod/兼容补丁、直接编辑上游。新独立工程采用自己的 packageId、Def 前缀、命名空间和产物路径；上游仍通过依赖/引用连接，不默认修改它或复用其身份。父目录中的示例配置不替代新工程自己的约定。

已有工程目录只证明已有内容，不能作为本次扩展的授权。完整 mod 可含多个功能块，各块记录范围，整体只验收用户要求的功能。

涉及素材或玩家文案时，按 [assets.md](references/assets.md) 明确本次必要资源、用户已有材料、可提供/复用项目与缺项状态。只请求真正需要用户提供的输入，技术规格由用途和加载接口确定；不把完整素材包设为所有任务前置。

在工程提供本项目 CLI 时：先 `snapshot` 得到基线，再修改；`check --profile L1 --baseline <文件>` 等按选定范围检查本次变化。已有有效环境可复用；第一次使用或版本改变时运行 `doctor`。其他工程使用自己的等价构建和检查，不强加本仓库的布局。

首次或命令无法执行时进入 rimworld-setup，只检查当前任务能力。目标工程实际提供 `tools/preflight.ps1` 时可先用它只读检查；没有则直接核对相关程序、游戏路径和查询能力，不运行不存在的脚本或套示例布局。不把全部 MCP 当作前置；已有环境可复用，不清楚目标时用 rimworld-help。

L5 需要把已选上游程序集加入真实编译引用，并分别核对运行时依赖和加载关系。L6 使用上游原有工程、引用和检查；本项目单程序集 CLI 不是所有上游的通用构建器。具体关系与操作矩阵见 [upstream.md](references/upstream.md)。

## 按功能闭环推进

1. 恢复本功能的已确认目标、限制、制作模式与记录，核对真实文件。
2. 确认用途、类型和执行链；先找可复用行为，再决定新 Def/类。内容连配置与行为，系统连入口/服务/状态，显示连事件/数据/筛选/输出。
3. 按 [contracts.md](references/contracts.md) 查相关配置、模板与合法默认，区分必需/条件必需/可继承默认/可选/技术未知。频率表只定核对优先级；真正未定的玩法值和资源按所选模式解决。
4. 准备必要资源，制作最小完整改动。按需读 [xml.md](references/xml.md)、[csharp.md](references/csharp.md)、[upstream.md](references/upstream.md)、[assets.md](references/assets.md)，无需全部加载。
5. 审核需求偏离、范围与端点连接，按 [verification.md](references/verification.md) 检查；源码需编译完整工程，模块完成后检查组合。
6. 修相关失败并复验，更新功能记录/索引/检查点。增量达标交付并等待新需求；不能游戏测试时留步骤与未验证项。

系统/显示主导任务读取 [runtime.md](references/runtime.md)。C# 占比不决定新级别；L3/L5 可完整交付无新增 Def 的 mod。混合 mod 按功能选择模式，不要求每块先创建物品。

修改接口后重新核对使用它的 Def 和调用方；改变引用后核对代码读取与加载。依据依赖关系失效相关证据，避免每轮重新生成全部文件。

## 工具与边界

- 原始 XML 证明模板、输入与补丁目标；运行时 Def 快照证明特定测试组合的最终值；源码/DLL 证明字段和行为。三者不能互相冒充。
- 先复用有效证据，再优先用已接通的 RimSage、RimSearcher、DecompilerServer、RiMCP 等做相关小查询，读取真实工具定义。不可用/版本不符/覆盖不足时说明原因并回退本地依据，保留缺口，不自动改客户端配置或每次重查全部。
- 空查询先检查命名、上下文、类型、加载列表和索引；无法确认关键外部接口时暂停依赖该接口的部分。新 Def 无须预先在游戏索引中存在。
- 允许为纯 XML 任务查看 DLL。成果扩展需符合用户范围；明确限制无法满足时说明原因并请求必要决定，其余已授权工作继续。
- 多个必要补丁允许共存；每个记录目标、目的、版本和作用范围。Prefix/Postfix 按执行时机选择，Transpiler 需说明其它方式为何不够。
- 通过需求选择与计划审视闸门后，范围内的制作、检查和编译连续完成；变化带来新的重大取舍时回到相关 Requirement/Plan。安装/发布/破坏性操作按实际授权处理。

## 交付

报告产出、范围检查、编译及已实测结果，列出未验证项。完整性取决于用户功能是否能获取、使用并表现正确；已有工程的小修不重建完整包。目标工程提供 `tools/mod.ps1` 和 `docs/cli-workflow.md` 时按其说明执行，否则用该工程的实际构建/检查。
