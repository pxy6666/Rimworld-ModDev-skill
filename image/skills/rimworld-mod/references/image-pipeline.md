# 图像生成与贴图交付

仅在任务需要生成/编辑图像或配置来源时读取。生图是资源分支，不改变六种制作范围，也不要求所有 mod 使用生成服务。

## 来源选择

本项目可用 `config/resources.example.json` 创建不提交的 `config/resources.local.json`；这是来源偏好，不是安装或连接证明。其他工程使用其等价配置。

| source | 执行方式 |
| --- | --- |
| auto | 检查当前会话实际能力，有内置图像工具时优先使用；没有时报告缺口/使用已授权的手动资源途径，不自动使用 API |
| builtin | 调用实际可用的内置图像工具及对应 imagegen 技能；平台名称不证明当前会话有工具 |
| connector | 按 connectorName/toolName 查找实际连接器，核对生成/编辑、透明背景、参考图与返回产物能力后调用 |
| imagegen-cli | 用户明确选择 CLI/API 来源时，按可用 imagegen 技能的官方脚本与凭证约定执行；没有适配能力就保留缺口 |
| manual | 使用用户交付的实际图像文件；可准备提示词供用户在外部平台执行，但状态仍是待生成 |

`model` 只对实际支持选择模型的 connector/CLI 有意义，不能为 builtin/auto 虚构模型参数。`credentialEnv` 只记录环境变量名，不写密钥值。配置不承载任意 shell 命令；连接器需要额外参数时按其真实接口做单独适配，不从来源配置执行代码。

配置已明确选择的来源可沿用；任务授权范围、凭证、消费限制和工具权限仍需实际满足。来源失败时记录已知失败与剩余工作；不要静默切换来源、模型或新增付费调用。不要把客户端整份配置或密钥写入提示词/回执。

## 从需求到可加载贴图

1. **资源规格**：从真实消费者（graphicClass/组件/UI）确定用途、目标目录、方向/变体、透明度、布局、shader 和绘制大小。用户描述造型和风格即可；像素尺寸与 drawSize 分开，不统一要求 64/256 像素或四向图。先查看参考图，区分风格参考与要编辑的原图，记录来源和使用条件。
2. **生成计划**：先通过 [制作循环](workflow.md) 的需求选择/计划审视，再把目标、风格、背景、视角和必须保持的内容写成提示词。明确小任务展示短计划并自检后可调用工具；多资源/需复用提示词时使用项目 `asset-plan` 和 brief 样例。样例不是当前用户要生成的内容。计划只记录规格与偏好，不生成图像、不验证服务。
3. **实际生成/编辑**：按已选来源的真实工具参数执行。在有 imagegen 技能的平台使用其流程；Codex 内置默认不需要 API key，CLI/API 分支仅在用户明确选择时使用该技能提供的脚本，不另写 SDK 运行器。透明资源设置真实透明背景；编辑使用实际原图和明确保持项。每个独立资源/变体按工具能力安排调用，不把图集或随机生成结果自动拆作合格方向组。
4. **产物落地与文件检查**：使用工具实际返回的图像/本机文件。内置输出可能在客户端生成目录，复制选定产物到项目，不能让 mod 依赖用户的临时目录。`asset-import` 导入真实本机 PNG，不联网下载、不改像素；它检查 PNG 容器/CRC、尺寸与是否具有 alpha 表示，并记录哈希与来源。容器通过不证明像素可解码、存在透明像素或没有棋盘格。
5. **视觉与绑定**：实际查看图片，核对可解码、轮廓、小尺寸辨识度、留白、真实透明度、方向和变体一致性。工具输出不满足尺寸/排布时按图像技能和用户授权做后处理，或重新生成，不静默使用未经授权的图像处理途径。确认实际加载目录（含版本/LoadFolders）、texPath 与图形类，再更新任务所需引用；`asset-import` 不自动改 Def。
6. **游戏验收**：检查相关对象/UI 的加载、方向、shader、比例与实际显示。没有游戏证据就提供复现步骤，不能把“生成成功”写成“贴图已完成”。

替换已有资产需符合用户明确的换图请求；否则保存兄弟变体。导入脚本默认拒绝覆盖，`--replace` 用于已授权替换并保存旧文件副本。资源导入可能立即改变连接到游戏的工程文件，按当前任务执行，不由 setup 检查触发。

## 最小记录

资源记录分开保存：来源/模型（实际可获知时）、提示词/参考、最终文件与哈希、消费者与规格、验证证据。状态依次可为待生成、已生成、已导入且容器已检查、已视觉检查、已绑定、已游戏验证；失败/缺失仍保留具体原因。自动回执只覆盖真实执行步骤，后续证据写入功能记录。

本项目 `asset-plan`/`asset-import` 是来源无关的计划与导入助手，不是跨平台生图代理。不同客户端通过其图像工具完成中间调用；纯终端无工具时可选择已支持的显式 CLI/API 分支或手动方式，无需改动 Def/C# 流程。
