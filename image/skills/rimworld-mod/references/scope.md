# 制作范围与成品

| 范围 | 允许的成果 | 重点 |
| --- | --- | --- |
| L1 原版局部数据/资源 | 目标补丁、既有自身 Def 的局部字段、文案或资源；独立包的元数据；不新增 Def、C# 或依赖 | 目标与最终值，或路径与视觉/声音 |
| L2 原版/DLC XML 内容 | Def、补丁、资源、语言；不新增自己的 C# 或 DLL | 模板、引用、获取与使用 |
| L3 原版/DLC 逻辑 | 自己的 C#、DLL、必要 Harmony/设置/语言；按需添加 Def 与资源 | 入口、接口、编译、行为、生命周期与状态 |
| L4 上游 XML/资源 | XML、资源、语言、已选定依赖；不新增自己的 C# 或 DLL | 上游接口/版本与条件加载 |
| L5 上游 C# | 自己的代码、DLL、已选定上游引用及必要适配；Def/资源按需；不自动修改上游工程 | 引用隔离、行为与跨 mod 兼容 |
| L6 编辑上游工程 | 用户授权的上游文件，遵守该工程约定 | 回归、公开身份和发行区别 |

这些是范围模板，不是必须依次通过的阶段。完整工程按功能块组合；用较宽模板也不允许制造需求无关内容。L1 中区分数值、图、声音、文案；引用其它 mod 进入 L4，但小改图仍只选相关检查。

## 实现模式：与六种范围独立选择

| 模式 | 常见目标 | 功能闭环 |
| --- | --- | --- |
| 内容主导 | 武器、建筑、配方、种族等 | Def/配置 → 行为 → 获取与使用 |
| 系统主导 | 全局规则、AI、管理服务或运行机制 | 启动/事件 → 处理服务 → 状态与行为变化 |
| 显示主导 | 伤害浮字、面板、覆盖显示与提示 | 事件/查询 → 数据筛选 → 显示/交互 → 清理 |

完整 mod 可混合模式。L3 的显示 mod 不必有新 Def；依赖上游公开类型的显示功能用 L5；直接修改上游工程用 L6。调用工坊 Harmony 按已有 L3 特例处理，不据此把所有原版补丁升级为 L5。

系统或显示功能读 runtime.md，只有真实需要配置或资源 Def 时才使用 XML 分支。不按 XML/C# 行数或百分比选分类。范围卡增加模式和入口：例如 L3/显示/standalone，入口为已查证的受伤事件，仅显示结果，不改变伤害结算。

交付形态：`edit` 修改已有工程；`standalone` 独立可加载 mod；`complete` 完整新功能；`release` 可发行包。独立补丁也需要 About/加载路径；完整功能可以全是 XML；发行形态额外要求干净打包和实际验证记录。

创建独立衍生内容或独立 patch，使用 L4/L5，拥有自己的工程与身份；直接修改上游才是 L6。L4 可以使用库的 XML 配置类，也可以引用普通内容 mod 的 Def；L5 可以调用内容 mod 的公开代码。制作范围不取决于上游被称为 lib 还是内容包。

范围说明至少包含目标、允许成果、明确限制与验收。建议例：L1/edit，只改指定伤害，允许目标 XML 与相关说明，不新增 Def/DLL/依赖，检查补丁和行为。

需要新增对象、程序集、依赖或全局补丁时先核对是否已获任务授权。已有授权可更新记录继续；违背明确限制或存在重大未决取舍时请求决定。允许查相关 DLL/源码。

修改前快照，完成后比较新增、修改和删除；既有 DLL 不应因本次 L1 修改被删除。脚本检查目录/元数据变化，语义审查检查用途与全局副作用。CLI 的 `--allow-dependency` 仅反映已授权选择，不授予权限。
