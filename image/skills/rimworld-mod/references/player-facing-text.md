# 玩家可见文本

制作或修改玩家能看到的物品与研究说明、任务信件、对话、地图提示、按钮或报错时读取。按项目已有用语和已确认样稿写作。在同一批次里先核对机制和玩家需要知道的事，再写文本和翻译。

## 按显示位置写

| 位置 | 优先回答的问题 |
| --- | --- |
| 名称与物品说明 | 这是什么，有什么容易忽略的用途。写可观察的材质、结构或用途。常规性能可由属性面板呈现。 |
| 研究说明 | 研究之后能做什么，现在怎样满足关键门槛。研究树已经清楚显示的前置可以省去。需要收集、购买或研读的特殊道具有必要时直接说清。 |
| 属性面板与选中状态 | 看基础属性或当前状态。基础属性注明单位和影响条件；燃料、当前功率、停转倒计时等动态信息由实际状态提供。 |
| 任务标题、委托信、事件通知 | 谁在说话，发生了什么，玩家现在能做什么。委托信可以有角色语气，事件通知强调已发生的变化，地图提示只透露当前角色或任务阶段允许知道的线索。 |
| 目标、按钮与反馈 | 目标能否直接操作，交互完成后会发生什么。禁用和失败提示优先给原因及可用的下一步。按钮使用短动作词，条件解释留给提示。 |
| 对话与剧情手记 | 先定说话人、已知信息和这一段的目的。用角色能看到的事物、惯用的称呼和具体要求表现性格。叙述长度由用途决定，关键操作容易从长信中找到。 |

## 写作与复查

1. 核对本次实际实现。看 Def、继承、相关 C# 与文本读取点，确认显示时机、条件、用途和异常结果。数值、类别和材料以实现为准。特性变动时核对本地化、Def 默认文案和同一功能的按钮、信件。
2. 批量写作时，先选项目认可的几条样稿和术语。调用或衍生上游内容时沿用已确认的物品名、派系称呼和游戏术语。将样稿中的语言习惯用于自己的文本，保留原有角色差异。项目没有文风约定时，从同语言、同显示位置的文本取样。不同作者版本可作为不同参考。
3. 删除开发者才需要的平衡比较、Def 名称和实施步骤。把无来源的卖点和氛围形容词换成能看见、能操作的细节。读一遍完整页面，减少相邻字段重复说明同一条件。玩家决策依赖的数值可直接展示，动态值优先从实际配置读取。
4. 同时检查 Def 默认文本、`DefInjected` 与 `Keyed` 的实际消费者。核对变量、语法规则、条件分支、XML 转义、颜色标签和换行。源文与译文表达同一事实，按各自语言组织句子。任务中至少抽查实际使用的出现、进行、完成或失败变体，并检查关键称呼和变量替换。

### 中文物品与研究起草及审稿 prompt

用于游戏里实际显示的物品与设施说明、相关研究说明，以及已有的属性面板和选中状态。输入目标版本、涉及的 Def 与实际行为、要改的显示位置、同类样稿和项目术语。

```text
把材料写成直接显示在 RimWorld 里的中文，只输出本次要写的字段。已有草稿时保留准确、自然的部分。
物品说明先说它是什么、能拿来做什么。用有依据的材质、形状或用途开头，优先留下名称或属性面板看不出来的功能，以及影响使用或摆放的限制。
研究说明先说解锁什么。需要玩家主动找、读、提交的特殊门槛要讲清楚；研究树和要求栏已清楚展示的条件可以省略。
属性面板写可比较的数值、单位和适用条件。需要区分原始数值及受品质等因素影响的实际值。选中状态写此刻的燃料、输出、倒计时或停机后的操作，动态值沿用实际读取点和已有变量。
先看目标版本的 Def、继承和代码，再决定哪些事实放在哪。玩家决策依赖的信息如无合适面板可看，就在现有说明或提示里保留。需要新增界面字段时作为独立实现项。
用具体动作和后果写，删掉与原版装备等级的开发对标、公式搬运和泛泛的卖点。保留重要条件、单位、专名、翻译键、变量和换行。已有样稿时沿用项目措辞。
```

### 物品与研究样稿对照

**米莉拉床 · 物品说明改前**

> 辉钢床架、羽仿布填充床垫的米莉拉床。不算品质，睡眠效果就已经相当于原版的大师级床。殖民者也可以坐在床上。

**物品说明改后**

> 辉钢床架上铺着羽仿布床垫。平时也能当座位。

**属性面板示例**　休息效率的基础值为 114%，实际值随品质等修正显示。取自 1.6 示例 `MiliraExtensionT_DownBed` 的 `BedRestEffectiveness = 1.14`。坐用是床的额外功能，留在物品说明。

**日光嬗变反应堆 · 研究说明改前**

> 建造日光嬗变反应堆：把日光燃料转化为电力，并顺带嬗变出少量普通物质的大型发电设施。接在太阳熔炉之后，并需要先研读米莉拉反应堆图纸。

**研究说明改后**

> 解锁日光嬗变反应堆。开始研究前，须先研读米莉拉反应堆图纸。

若当前界面已清楚显示太阳熔炉前置，可省略这项复述。反应堆的实际用途由建筑说明交代。

**物品说明改前 · 节选**

> 4x4 的反应堆，以日光燃料为燃料（容量 800）。运转时每天消耗 20 燃料，发电 5000 W，另按燃料剩余比例最多再加 15000 W。

**物品说明改后**

> 消耗日光燃料发电。运转时，燃料越充足，输出功率越高，还会生成少量物资。长时间缺料会停机，补充燃料后需要手动重启。

**属性面板与选中状态示例**　可用的静态属性栏可展示运行时功率范围 5,000–20,000 W、燃料容量 800 和消耗 20／天。选中状态沿用现有检查信息，例如“没有燃料：{0} 天后停转”，已补料但待重启时提示所需智识等级。上述数值与条件取自 1.6 示例的 `V6_Reactor.xml` 和 `CompInspectStringExtra` 等实现。面板示例说明信息放在哪儿，采纳时核对当前界面实有的字段。若界面看不到会影响选址、补给或重启的条件，应在已有说明或提示保留。

## 剧情与角色口吻

1. 用角色对眼前事情的反应带出设定。有人护住一块门牌，玩家就有机会明白这块门牌值什么。角色需要交代的背景留在他此刻有理由说出来的地方。
2. 尽量让一句话只说一件角色当下在意的事。逐句核对他此刻要提醒、遮掩、求助还是催促，把关系、规矩和行动分到各自站得住的句子里。
3. 按角色的立场、所知和偏见写。让他只说亲眼见过、听说过或自己相信的事，必要时让读者听得出他在猜。打断、改口、重复和半句可以表现犹豫、紧张或藏话，在这些反应有作用时再用。对话里少插旁白式描绘。
4. 有后续互动时，最后尽量留一个可用的线索或行动，例如地点、入口、物件、约定时间或要问的人。任务目标单独写清玩家现在能做什么、做到哪一步算完成。

同一则原创委托的三种文字可这样落位。

- **背景底稿**　巡查员按门牌登记发放口粮。配给册存放在档案室，锅炉房有侧门可通往那里。
- **角色台词**　“别碰门牌。巡查员找不到我弟的名字，就不给他发口粮。上回已经……拿着钥匙。从锅炉房进档案室。”
- **任务目标**　从档案室取回配给册，交给委托人。

### 中文剧情起草与审稿 prompt

用于玩家实际看到的剧情公告、信件、对白、手记、任务线索和相关剧情提示。提供开发笔记或草稿、显示位置、当前剧情阶段，以及用户审过的样稿（如有）。物品和研究另用[物品与研究 prompt](#中文物品与研究起草及审稿-prompt)。

```text
把提供的材料写成能直接放进游戏的中文剧情文本。已有草稿时，保留成立的句子，只改影响口吻、信息顺序或玩家理解的部分。
每段先确定说话者、听众、此时知道什么，以及这句话想让对方做什么。
公告保留发令者的语气，写清要交什么、交给谁、谁要随队。角色对白从眼前的物件、自己的反应或对方刚问的话接起。每句尽量推进一件角色当下在意的事。
沿用已确认的剧情、事实、确定程度、术语和游戏内可执行的动作。材料里还没确定的动机、证据和情节先留白。有用户审过的样稿时，参考它的用词、句长和反应方式。
写完遮住角色名读一遍，再按实际显示顺序检查玩家能否找到下一步。让明确的任务目标承担数量、交付时机和完成条件。
只输出可展示的游戏文本。需要同时保留的变量、翻译键和换行规则按原要求处理。
```

### 样稿对照

**米利安巡查队公告 · 改前**

> 〔批号〕餐食发放后，数名食用者就医。尚有留样未收回。持有留样者须封存原盒，交米利安巡查队收运。烹制人随队移送问询。收留烹制人的地点列入本次搜查。

**米利安巡查队公告 · 改后**

> 〔批号〕这批饭发下去后，已有几人就医。留样还没收齐。手里有留样的，把原盒封好，等米利安巡查队来收。做这批饭的人须随队问话。收留此人的地方，一并搜查。

公告保留正式指令。“把原盒封好”能让收件人立刻知道要做什么，末句仍交代搜查范围。

**厨师 · 改前**

> 那批是我做的。出厨房的时候，箱子封着。你看这张单，谁领走的，上面一个字都没有。

**厨师 · 改后**

> 那批是我做的。箱子出厨房的时候还封着呢。你看这张单子，上头有领饭人的名字吗？

厨师保留对自己经手那一段的确认，接着把对方的注意力引到单子上。领饭人身份依然未知。

### 关键场景的通读验收

关键对白较多时，选一场玩家已审过的戏作为项目样稿，记录各角色怎么说话、怎样判断和在哪里承认自己不知道。后续按同一套方法通读相关场景。

1. **遮住名字读。** 从用词、反应和回避的问题判断谁在说话。两人台词互换后依然成立时，回看他们各自来这场会面想达成什么，以及各自愿意说到哪里。
2. **按出场顺序读。** 写下一场开始时玩家知道什么，结束时哪些疑点、判断或选择发生了变化。相邻两场都提到同一件事时，检查后场有没有确认、推翻或补充前场，或在玩家实际需要时提供回顾。
3. **按玩家当时能看到的内容读。** 顺着真实触发次序看地图、对白、按钮、任务更新与目标。玩家应能判断为什么去、去了怎么回来、在哪一步交付。台词可以留线索和人物节奏，任务目标写清触发条件、数量和完成时点。若关键线索在某条路径上看不到，核对此前的信息和可用的任务提示。

## 本地 XML 样本定位

下列锚点来自本机工坊发行内容的只读抽样。以文件角色和显示位置为观察单位，可在本机工作区的 Steam Workshop 根按物品 ID 查找。参考文本结构、信息排序和变量处理。样本属于静态发行文件，具体语言与启用组合取决于实际项目。

| 样本 | 观察到的做法与定位 |
| --- | --- |
| Milira Race · `3256974620` | 简中物品说明先给外观或佩戴位置，再说明实际动作及效果，见 `Milira_Apparel_AttractiveGrenade.description`（`ThingDef/Apparel_Belt.xml`）。轨道任务先交代发现和环境，接着提示停靠方式与出发前准备，见 `Milira_OpportunitySite_Asteroid_SolarCrystal.questDescriptionRules.rulesStrings`（`QuestScriptDef/Scipts_Space.xml`）。 |
| Milira Faction: Milira Imperium · `3588393755` | 角色来信可以很短，事件结果紧随其后，见 `PrivateerCaptainJoin.letterText`。路线可按委托人条件替换任务开头，见 `Milira_FallenAngel_ToImperium` 的任务规则。对照 `MI_QuestScript_Defector_I` 与 `MI_SitePart_Defector_I` 可以检查任务与地点页各自需要多少重复背景。 |
| [OA]Ratkin Faction: Oberonia aurea · `3159926804` | 装备介绍可把制服用途和会影响比较的流血倍率分段，见 `OA_RK_Professional_Uniforms_D.description`。缺料提示用参数填具体物品与数量，见 `OAFrame_NeedCountOfThing`。 |
| Vanilla Furniture Expanded - Power · `2062943477` | 研究说明常先列已解锁的设备，再给设备的用途，见 `ResearchProjects_2_Electricity.xml` 中的 `VFE_IndustrialGenerators` 和 `VFE_AdvancedPowerSources`。研究说明与建筑说明可各自承担不同信息。 |
| Vanilla Quests Expanded - The Generator · `3411401573` | 长任务可以按委托人身份改变开头，地点说明仍可保持一句话。对照 `VQE_PrototypeARC`、`VQE_Quest1Site.description` 和 `VQE_InstallWoodFiredGenetron`，可分别看任务、地点和按钮承担多少信息。 |
