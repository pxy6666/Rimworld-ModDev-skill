# 批量图形、选稿与视觉验收

遇到沿用已选样稿重绘、跨款式或朝向制作、地图图与图标配套、拼接或透明叠层时读取。普通单图替换沿用 [资源短流程](assets.md)。本页补足选稿、映射和视觉验收；来源、技术规格和制作授权仍用现有规则。

## 从选稿到一批成品

1. **恢复本批基准。** 从已有项目记录预填适用的风格修订号、认可样稿和不动项。样稿用稳定 ID 与工程相对路径定位；路径可能被覆盖时再记文件哈希。标明参考图是要编辑的原图，还是仅参考轮廓、配色、线条、遮挡或细节密度。项目色卡和参考图留在项目；单件反馈仅在用户同意推广时成为长期风格。
2. **先测最容易出错的代表稿。** 多朝向、拼接或贴格物件先看同尺度格线图，按需看并排、侧面、图标小尺寸或不同状态。区分像素画布、透明边界、地格锚点、占格与绘制大小。不默认每件都要四张方向图或同一尺寸。
3. **沿用选定稿批量推进。** 在已有计划和资源模式内锁定保留项及可变项。只有新取舍会改变外观或扩大范围时才确认；已有明确选择直接用，局部反馈只重做受影响的部分。已有素材可直接准备和检查，工具不可用时标出尚缺的成品。

需要生成或编辑位图时按 [图像管线](image-pipeline.md) 使用实际可用且获授权的来源：先验证代表稿，再做剩余款式；不要把一张随机图集当成方向验收。

## 按消费者核对

沿用现有功能或资源清单，按需记录 `目标版本 / Def、组件或界面 / 用途 / 款式 / 朝向、状态或拼接组合 → 文件与证据`。从实际生效的引用与加载根追到文件，分别核对菜单图标、地图贴图、透明叠层和粒子。文件名存在不代表实际 A/B、方向或变体映射正确。

| 关注点 | 只在涉及该风险时检查 |
| --- | --- |
| 多朝向、贴格、拼接 | 同尺度检查轮廓、地格锚点、透明边与并排接缝；实际地图再查旋转、邻接和遮挡。 |
| 款式与状态 | 对照预期映射，分别查地图与图标消费者；运行态、选中或切换效果按相关场景复验。 |
| 透明层和特效 | 检查真实 alpha、小图可读性及叠层锚点；实机核对遮挡、开关、远近或昼夜表现，静态对照不证明运行时绘制。 |

单独记录实际达到的阶段：**样稿已选 → 文件已看 → 工程已绑定 → 本机已同步 → 游戏内已验证**。只做到样稿、素材或工程时停在约定交付阶段。需要同步且已有授权时核对实际副本、路径及哈希；没有新游戏证据就写待测场景，不把同步当成已显示。

## 交回版本制作或排错

素材负责图和规格，绑定修改、绘制顺序、运行时切换或特效触发交对应目标版本的制作流程；现有资源和绑定都正确但显示仍异常时交版本排错。交接目标、已选稿、授权范围、消费者、复现和未验证项，沿用原计划。仅换图不自动授权加 DLL、改运行逻辑、覆盖无关资源、写游戏目录或启动游戏。

## 可复制的简报

- **范围和基准**：物品/款式，沿用的风格修订或已选样稿。
- **这次要改／请保留**：最重要的部位与不动项，必要时补参考及用途。
- **交付与怎么看**：样稿、完整素材或已绑定工程；只列要核对的方向、比例、图标或游戏场景。

能从记录确认的由代理预填。已有项目文件能承载这些信息时，无须再建台账。
