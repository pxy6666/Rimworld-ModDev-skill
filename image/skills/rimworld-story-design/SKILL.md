# RimWorld 剧情设计

恢复相关[功能记录](../rimworld-mod/references/project-state.md)。整理用户已有的设定、目标版本、允许的 DLC、玩法限制和已定方向。已有完整结构时只补影响实现或验收的缺项。

1. **共同构思与初查。** 概念模糊时，先用玩家能理解的语言列出玩家是谁、会做什么、为何继续、哪些选择会改变结果。给出具体选项、推荐路线或状态图之前，先按 [剧情可行性](../rimworld-mod/references/quest-feasibility.md) 核对会改变方案的玩家动作和演出。说明实际会看到什么、哪些已有对应手段、哪些需要新逻辑或待查。每轮集中比较一两个重要取舍，试走一条代表性流程，再记录确认项。
2. **设计入点。** 对开局剧本记录 `Scenario` / `ScenPart` 的候选入口、初始地图或对象，以及玩家何时能开始行动。对中途触发记录交互对象、地图发现、叙事者事件或前一任务等来源，以及资格、拒绝和错过后的结果。多入口共用同一条故事时，决定汇合的状态和首次初始化条件。适用时说明已有存档能否进入，以及重复发现或两个入口先后触发时怎样处理。
3. **设计阶段与终点。** 逐段写清玩家动作、可观察的反馈、下一阶段需要继承的选择或人物、场景需求和成功条件。区分抵达、取得目标、撤离与交付。各结局给出可观察的变化和长期影响。给出失败、放弃或目标丢失后的去向，注明能否重试、重试条件与保留的进度。
4. **展示状态图。** 剧情结构确定后，在实施计划审视时展示简短的 Mermaid `flowchart`。节点用玩家能识别的阶段，边写实际触发或选择，显示入点、必经阶段、结局与允许的重试。单次事件可用短流程，无法渲染时用阶段表。图和文字提纲来自同一组阶段与条件，变更时一起更新。
5. **交接。** 交付简短提纲，复杂剧情附状态图。把现有决定、关键场景、未决项与验收草案放进[同一份功能记录](../rimworld-mod/references/feature.md#任务与地图交接)。需要制作时按[专项交接](../rimworld-mod/references/quest-chain.md)回主流程继续。

交接保留初查来源、实际呈现与未验证假设。实施分支用目标构建核实真实入口。玩家看到的对话、叙述或线索按 [剧情与角色口吻](../rimworld-mod/references/player-facing-text.md#剧情与角色口吻) 起草。
